## ✨ Feature Overview

### Report Waste Incidents
Kitchen staff can report when ingredients are wasted:
- **Spoilage:** Expired, discolored, odor issues
- **Spillage:** Dropped, broken containers, accidents
- **Other:** Any other waste category

### Track Everything
- What ingredient was wasted
- How much (with unit: kg, L, pieces, etc.)
- Why it was wasted (from predefined reasons)
- Where in the kitchen (Fridge, Freezer, etc.)
- Who reported it and when
- Estimated cost (auto-calculated)

### Auto-Update Inventory
- Waste reported → Inventory automatically deducted
- Low-stock alerts → Triggered if stock drops below threshold
- Daily stats → Auto-aggregated by type, reason, shift

### Real-Time Dashboard
- New "Waste & Spoilage" tab in Kitchen Dashboard
- Summary stats (today, week, month totals + costs)
- Reports list with filtering and pagination
- Charts showing waste trends and breakdown

### Export & Report
- Generate Excel reports with details and summaries
- Create PDF reports with charts for management
- Time-range analysis and cost tracking

## 🔌 API Endpoints

```
POST   /api/waste/report
       └─ Submit waste incident
       
GET    /api/waste/reports?page=1&limit=20&filters
       └─ List reports with pagination
       
GET    /api/waste/stats?period=day|week|month
       └─ Get statistics and summary
       
GET    /api/waste/reports/:id
       └─ Get single report details
       
PUT    /api/waste/reports/:id/resolve
       └─ Resolve report (manager only)
       
DELETE /api/waste/reports/:id
       └─ Delete report (admin only)
       
GET    /api/waste/export?format=excel|pdf&date_range
       └─ Export waste reports
       
GET    /api/waste/trends?metric=quantity|cost&period
       └─ Get trend data for charts
```

## 🗄️ Database Schema

### New Tables

**waste_logs** (Main table)
- id, restaurant_id, ingredient_id
- waste_type, quantity_wasted, unit
- reason, description, notes
- reported_by_user_id, timestamp_reported
- estimated_cost, batch_id
- location_in_kitchen, shift
- is_resolved, manager_notes, resolved_at
- 11 performance indexes

**waste_categories**
- id, restaurant_id, category_name
- category_type, target_waste_percentage
- 5 default categories pre-inserted

**waste_statistics** (Daily aggregates)
- id, restaurant_id, date_recorded
- total_waste_quantity, total_waste_cost
- waste_count, spoilage_qty, spillage_qty
- top_wasted_ingredient, shift breakdowns

**waste_audit_log** (Compliance)
- id, waste_log_id, action
- action_by_user_id, action_timestamp
- old_values, new_values (JSONB)

### Automated Features
- Trigger: Auto-deduct from inventory (spoilage movement)
- Trigger: Auto-update daily statistics
- View: Recent waste reports (last 30 days)
- View: Unresolved reports (for managers)
- View: Daily waste summary

## 🔐 Security Features

```
Authentication
└─ JWT tokens required for all API calls

Authorization (RBAC)
├─ Kitchen Staff: Report, view own reports
├─ Manager: Report, view all, resolve, export
└─ Admin: All + delete, manage categories

Row-Level Security (RLS)
└─ Database-level isolation by restaurant

Input Validation
├─ Server-side validation (not trusted client)
├─ Cost calculated server-side
└─ XSS & SQL injection protection

Audit Trail
└─ All actions logged to waste_audit_log
└─ Timestamp, user, old/new values
└─ Compliance-ready for food safety audits
```
